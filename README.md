# Streamstats — потоковый анализатор логов

Лабораторная работа №2 по дисциплине «Программирование на языке Python».
Консольное приложение читает логи в форматах CSV и JSON Lines, проверяет записи, накапливает статистику и формирует JSON-отчёт. Файл читается построчно: в памяти хранятся только счётчики.

## Структура проекта

```
.
├── src/
│   └── streamstats/
│       ├── __init__.py
│       ├── __main__.py   # CLI, логирование, коды возврата
│       ├── parsers.py    # ленивые парсеры CSV и JSONL, реестр форматов
│       ├── models.py     # событие и его валидация
│       ├── analysis.py   # статистика и политика обработки ошибок
│       ├── report.py     # сборка и запись JSON-отчёта
│       └── errors.py     # собственные исключения
├── tests/
├── pyproject.toml
└── README.md
```

Путь данных: файл → парсер (генератор) → валидация → статистика → отчёт.

## Использование

```powershell
python -m streamstats analyze INPUT [INPUT ...] --format csv|jsonl [--output REPORT.json] [--skip-invalid] [--log-file LOG]
python -m streamstats --help
```

- `--format` — формат входных файлов (`csv` или `jsonl`).
- `--output` — файл для JSON-отчёта; без него отчёт печатается в stdout (в stdout только JSON, сообщения идут в stderr и в лог).
- `--skip-invalid` — пропускать повреждённые записи с предупреждением вместо остановки.
- `--log-file` — файл лога (по умолчанию `streamstats.log` в текущей папке).

Примеры:

```powershell
python -m streamstats analyze app.csv --format csv --output report.json
python -m streamstats analyze a.jsonl b.jsonl --format jsonl --skip-invalid
```

## Входные данные

Событие: `timestamp` (ISO 8601), `level` (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`), `source` (непустая строка), `message` (строка).
CSV содержит строку заголовка; JSONL — по одному JSON-объекту в строке.

## Отчёт

```json
{
  "total_events": 3,
  "levels": {"DEBUG": 0, "INFO": 1, "WARNING": 0, "ERROR": 1, "CRITICAL": 1},
  "sources": {"api": 1, "db": 1, "сервер": 1},
  "top_error_sources": [{"source": "db", "count": 1}, {"source": "сервер", "count": 1}],
  "first_timestamp": "2026-10-07T12:00:00+03:00",
  "last_timestamp": "2026-10-07T12:10:00Z",
  "skipped_lines": 1
}
```

(в файле JSON записан с отступами). Статистика нескольких файлов объединяется в один отчёт.

## Ошибки и коды возврата

- По умолчанию при первой же ошибке обработка останавливается, в stderr и в лог выводятся имя файла и номер строки (`data.csv:3: unknown level 'LOUD'`), код возврата **2**.
- С `--skip-invalid` повреждённая строка пропускается, в лог пишется WARNING, число пропусков попадает в `skipped_lines`.
- Успех — код **0**. Ошибки аргументов командной строки тоже дают код 2.
- Собственные исключения: `StreamStatsError` (база), `UnsupportedFormatError`, `InvalidEventError`, `InvalidTimestampError`, `CliConfigurationError`.

## Логирование

Модули пишут в логгер `streamstats.*`, настраивает его только CLI: сообщения идут в консоль (stderr) и в файл лога, который остаётся после работы. Фиксируются начало и конец обработки каждого файла (число событий и пропусков), каждый пропуск (WARNING) и фатальная ошибка (ERROR).

## Принятые решения

- Временная метка без часового пояса считается UTC. Метки сравниваются как моменты времени с учётом пояса; в отчёт попадает исходный текст первой и последней метки.
- Уровень — строго заглавными буквами. `source` — непустая строка (из одних пробелов — пустая); пустой `message` допустим.
- Отсутствующее поле и пустое значение — разные ошибки. В JSONL `null` считается отсутствующим значением; в CSV отсутствующим считается значение в слишком короткой строке.
- Повреждённая строка: некорректный JSON, JSON не объект, CSV-строка с лишними значениями.
- Номера строк относятся к исходному файлу (заголовок CSV — строка 1). Пустые строки JSONL пропускаются, но нумерацию не сбивают.
- Пустой файл (или CSV только с заголовком) даёт отчёт с нулями и `null`-метками.
- Топ-5 источников ошибок ERROR/CRITICAL упорядочен по убыванию числа, затем по имени источника.
- Детерминированность: порядок ключей в отчёте фиксирован, в отчёте нет времени запуска и путей, поэтому одинаковый вход даёт побайтово одинаковый результат; порядок файлов не влияет на статистику.
- Все файлы читаются как UTF-8 (BOM допускается), отчёт всегда записывается в UTF-8.
